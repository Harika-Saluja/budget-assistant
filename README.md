# Budget assistant: a memory you can inspect, correct and forget

README prose word count: **[fill in after editing]** (code and commands not counted)

A coursework prototype for *Intelligent Interactive Systems*. A chat assistant answers questions about
**synthetic** spending data and remembers things about the user. Its memory sits in a panel beside the chat, where
each note can be confirmed, edited or forgotten. Not financial advice. It never moves money.

## Technology stack

- Python 3.10+; Streamlit for the UI; standard library for everything else (`core.py`, `checks.py`, `tools.py`).
- Storage: local `memory.json` (git-ignored).
- Model: optional. `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`, and optionally `BUDGET_MODEL`. No key: the app replays
  recorded live replies from `recordings/` where they exist, otherwise gives a rule-based demo reply.
- **No API key is committed.** A reviewer can supply their own as an environment variable.

## Running, replaying and inspecting

```bash
pip install -r requirements.txt
streamlit run app.py                 # works with no key: replay or demo mode
python -m unittest -v                # tests of the core logic; no network or key needed
```

Live model (your own key):

```bash
export ANTHROPIC_API_KEY=...         # PowerShell: $env:ANTHROPIC_API_KEY = "..."
streamlit run app.py
```

Recording a demo so others can replay it without a key (use synthetic data only):

```bash
BUDGET_RECORD=1 streamlit run app.py   # PowerShell: $env:BUDGET_RECORD = "1"
# ask the demo questions, then commit recordings/live_responses.json
```

The sidebar shows which mode is active, the seven stages of the last model call, and what was sent.

## Data

Transactions are generated by `make_transactions()` (seeded, so reproducible) and include one planted one-off payment.
The sidebar can download them as CSV and upload a CSV with columns `date, merchant, category, amount`. Don't use real
bank data in a public repository or deployment.
